## 1. Overview of this update

- Fixed all 9 defects reported in QA run `20261003-computer-use-v1` (5 at P2, 4 at P3).
- The main change is one rule for "unsaved". Undoing a title, Markdown preview or speaker-notes edit back to the saved state left the document marked unsaved. At the same time, the changes label said it matched the last save. One rule now decides both, so the footer, the tab marker and the changes label agree (BUG-001, BUG-005, BUG-007). Two edge cases with blank Markdown tabs remain (KI-49, KI-50).
- These defects were also fixed:
  - the find bar after undoing a replace (BUG-002)
  - how the Slides tabs are announced (BUG-003)
  - input checks in Go to Line (BUG-004)
  - Esc for the Review panel (BUG-006)
  - the export formats listed in Help (BUG-008)
  - the slide position after a presentation (BUG-009)
- After the fixes, the whole change was reviewed, and the problems found were fixed too. The main ones:
  - Clicking Replace in the find bar while typing in a Markdown Preview paragraph discarded the typed text (data loss that predates this release).
  - Opening Presentation mode left key presses going to the document behind it.
  - A few special cases showed unsaved changes as Saved.
- Most of this release is bug fixes, but it also changes how some things work, so the minor version goes up to 1.5.0. The main changes are that Esc closes panels, ⌘Z works differently in the notes field, and Go to Line checks its input. Section 2.3 lists the changes.
- **The new build has not yet been checked in the running app.** All automated tests pass (section 5). Every known problem is listed in section 3 (Known Issues), and every feature not yet built is listed in section 4 (Future Release).

### 2.2 Bug fixes

**Unsaved state and Undo**

- Pressing ⌘Z in the title field back to the saved title left the document unsaved. It now returns to Saved once the content matches the last save (BUG-001).
  - For Markdown files, the H1 line's original formatting and blank lines are restored byte for byte.
  - Markdown source edits made before the title edit are never rolled back.
  - Title edits are still not part of the document's Undo history (KI-06).
- Adding a paragraph with "+ Add paragraph" in the Markdown preview and undoing it with ⌘Z left the document unsaved. Undoing any edit made after switching to Markdown or Slides now also returns to Saved (BUG-005).
- Speaker notes reached the document only when the field lost focus (BUG-007). That caused these problems:
  - While typing, the footer stayed "Saved" and Undo was disabled.
  - The first click on a tab's close button did nothing.
  - After Undo, the field and the document disagreed.
  - A mode switch made the note seem to vanish.

  Notes now reach the document as you type. A run of typing undoes in one step, and Japanese IME conversion never splits a step.
- The bullets field of a detached slide had the same problem as speaker notes. It now writes as you type, and a typed empty line or trailing space stays while you type.
- The footer's "Unsaved" and the changes label were decided by two different rules. One rule now decides both. Typing the saved text back in also returns to Saved.
- In three cases, a changed document read as Saved and closing it did not ask to save. All three happen in the Markdown view:
  - select all and delete in a `.md` that held only a heading
  - typing a heading into an empty `.md`
  - deleting the content of a `.md` saved from the Editor view
- A document whose only change is an AI version swapped back to the original also reads as unsaved, which protects the version history stored in `.aix`.
- Text typed while a save was still writing joined the typing before the save in one Undo step, so Undo could not stop at the saved state. A save now ends the Undo step when it starts (Editor and Slides).
- Text typed after a relationship analysis joined the analysis in one Undo step, so one Undo removed both.
- In detached-slide bullets and speaker notes, keystrokes that store nothing, such as spaces, did not keep the typing step open, so slow typing split into one Undo step per word.
- In the Markdown source, ⌘Z right after the document changed elsewhere (a replace, or Edit → Undo) could re-apply the change that had just been undone. Changes from outside the source are no longer recorded in the source's own Undo history.
- In Markdown with mixed line endings, Edit → Undo recorded an extra step and Redo stopped working.

**Find and Go to Line**

- After Replace All in the Markdown source, ⌘Z / ⇧⌘Z left the find bar stale: the count and the buttons were not updated, and "Replaced N." stayed on screen. Matches are now recomputed from the current text however it changes, in the Editor too (BUG-002).
- Go to Line accepted 0, numbers past the last line, negative numbers and decimals, and silently jumped to the nearest line (BUG-004).
- Clicking Replace or Replace All in the find bar while typing in a Markdown Preview paragraph discarded the typed text.
- A Replace All that changes nothing (for example, every match already reads the replacement) said "Replaced N.", and the next ⌘Z undid an unrelated edit. It now says "Nothing to change." and is not an Undo step.
- Turning Match case or Whole word on or off after Replace All kept "Replaced N." on screen.
- After a document Undo, the selected match's position ("1 / 3") was shown as "3 matches".
- When the status text changed length, the ↑ and ↓ buttons moved and a click could miss them.

**Slides and Presentation**

- Assistive technologies such as VoiceOver could report both the "Edit slide" and "Preview slide" tabs as selected. Only the tab on screen is now reported as selected (BUG-003).
- Ending a presentation went back to the slide selected before it started (BUG-009).
  - The slide on screen at the end is now selected, and the next presentation starts there.
  - This is the same whether you exit with Esc, the × at the top right, or the "Esc to exit" button.
  - It does not mark the document unsaved.
  - In the Edit view, the caret returns to a paragraph of that slide.
- Starting a presentation from the command palette left focus in the document behind it, so key presses changed the document. The presentation now takes focus when it opens.
- The slide diagram notices said diagrams were "not yet exported to .pptx", but they were exported on slides with an image layout. The notices now describe what actually happens.

**Keyboard**

- The Review panel did not close with Esc (BUG-006). The other panels and popovers now close with Esc too, including KI-35 from v1.4.0.
- With a comment not yet added in the Review panel, Esc could close the panel and discard the comment. With such a comment, Esc now keeps the panel open and moves focus to the comment.
- With any of these open, one Esc could also close an open panel or another menu. One Esc now closes only one thing.
  - the Markdown preview's Background menu
  - a link popover
  - a toolbar menu
  - the find bar
- The panels that open in the bottom-right corner (Review criteria, Personal library, Citations) could overlap, and Esc could close the hidden one. Only one of them is open at a time now.
- The formula (TeX) editor did not close with Esc while its input had focus. Esc that cancels a Japanese IME conversion still leaves it open.
- The link popover closed on the Esc that cancels a Japanese IME conversion.

**Help**

- Help section 6, "Save & export", did not list PPTX among the export formats (BUG-008).

### 2.3 Behavior changes (things to know when updating)

| Change | Before | This version |
|---|---|---|
| ⌘Z in speaker notes and detached-slide bullets | The field's own Undo | The document's Undo. A run of typing undoes in one step, the same as Edit → Undo |
| Esc | Closes dialogs, the find bar and toolbar menus | Also closes panels and popovers (section 2.1), including while the caret is in a paragraph. In the Markdown source, the title, a dialog, the find bar or a field inside a panel, Esc stays with that field and does not close the panel |
| Go to Line | Out-of-range values jump to the nearest line | Anything but a whole number from 1 to the line count does not move |
| Whitespace-only edits | Not counted as a change in the changes panel | Counted as a change (the document becomes unsaved and the edit is listed in the changes panel) |
| Returning to the saved content | Sometimes stayed unsaved | Returns to Saved |
| Ending a presentation | The slide selected before the presentation stays selected | The slide on screen at the end is selected |
| ⌘Z in the Markdown source right after the document changed elsewhere | Undid that outside change (a replacement that had just been undone could come back) | Does nothing. Once you type in the source, ⌘Z works again from that typing. Edit → Undo always works |
| Bottom-right panels (Review criteria, Personal library, Citations) | Several could be open at once | Opening one closes the other two |
| A Replace All that changes nothing | "Replaced N." | "Nothing to change.", and it is not an Undo step |
| Close-button tooltips | "Close panel" and similar | "Close panel (Esc)", "Close (Esc)" |

- The Tauri permission settings (capabilities) and the CSP are unchanged.
- For each fix, a test that fails without the fix was written first and seen to fail before the fix went in.
- After the fixes, the whole change was reviewed from 7 angles: data safety, Undo, keyboard, find, slides, test quality and UI. Of 25 findings, 21 survived attempts to refute them. All of them were fixed except one, the difference between the preview and the PPTX for a diagram-only slide, which is listed as KI-51.
