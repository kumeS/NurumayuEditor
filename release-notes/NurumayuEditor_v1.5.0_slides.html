RELEASE 1.5.0 · 2026-10-18 · macOS

NurumayuEditor v1.5

One rule for unsaved changes, live notes, Esc-closable panels and a safer find bar.

Write Markdown. Preview it. Present it.

NurumayuEditor v1.5.0 was released on 18 October 2026, 16 days after v1.4.0. It fixes all nine defects reported in QA run 20261003, five at P2 and four at P3. The main theme is one rule for unsaved: the footer, the tab marker and the changes label now agree, apart from two edge cases with blank Markdown tabs. Most of the release is bug fixes, but Esc, ⌘Z in the notes field and Go to Line now behave differently, so the minor version goes up. The new build has not yet been checked in the running app.

What is NurumayuEditor?

A local-first Markdown and slide editor built on chunks.

One file, two faces

The same chunks are your document and your deck.

AI per chunk

Translate, proofread, expand, diagram, in context.

Your own library

Grounded in your notes and papers, on-device.

STACK

Tauri · Rust · React

FILES

.aix / .md → PDF, PPTX

MODELS

OpenRouter or Ollama

SECURITY

Keys in OS keychain

A scratchpad for weekly progress, not a finishing tool

NurumayuEditor treats a document as an ordered list of chunks, like notebook cells for writing. That list is projected two ways: a document you edit and a deck you present, with no export step in between. Each chunk is also the unit for AI actions (translate, proofread, expand, summarize, diagram, illustrate), which read the surrounding context and can draw on a personal library kept entirely on the device. API keys live in the OS keychain and all network calls happen in Rust. It is meant for rough weekly progress; final polish still happens in your usual apps.

By the numbers: 9 QA bugs fixed · review: 25 findings, 21 confirmed, 20 fixed

Source: release notes v1.5.0 · §1, §2.1, §2.2, §5

Six headline changes. Top row, new behavior. Esc now closes the Review, relationship graph and changes panels, the status-bar popovers, and the Review criteria, Personal library and Citations panels. With several open, one Esc closes one panel: the one you are in, else the most recently opened one. If focus was in that panel, it goes back to where it was before the panel opened. Esc does not close panels while the caret is in the Markdown source, the title, a dialog, the find bar or a field inside a panel, during Japanese IME conversion, while a dialog is open, or in Presentation mode. An edit that changes only the Markdown source, such as front matter, blank lines or line endings, is named "Markdown source changed" in the status bar and explained in the changes panel. Go to Line accepts only whole numbers from 1 to the line count; full-width digits are fine, and anything else disables Go with an inline message (BUG-004). Bottom row, fixes. One rule now decides the footer, the tab marker and the changes label, so undoing back to the saved title, Preview or notes returns to Saved (BUG-001, BUG-005, BUG-007); two blank-Markdown-tab edge cases remain, and title edits are still outside the document's Undo. Speaker notes and detached-slide bullets reach the document as you type, and a run of typing undoes in one step. After Replace All and ⌘Z the find bar recomputes its matches instead of going stale (BUG-002). Also fixed: only the tab on screen is announced as selected in Slides (BUG-003), and Help section 6 now lists PowerPoint export in all five languages (BUG-008); PPTX export itself is not new. All nine QA defects are fixed. The review of the whole change raised 25 findings; 21 survived refutation and 20 were fixed.

Source: release notes v1.5.0 · §1, §2.2, §2.3

Left: three problems the review of the whole change found, all about data. Clicking Replace or Replace All in the find bar while typing in a Markdown Preview paragraph discarded the typed text; that data loss predates this release, and the text is now kept. In three Markdown-view cases a changed document read as Saved and closing it did not ask to save: select all and delete in a .md that held only a heading, typing a heading into an empty .md, and deleting the content of a .md saved from the Editor view. Starting a presentation from the command palette left focus in the document behind it, so key presses changed the document; the presentation now takes focus when it opens. Right: changes users will notice on upgrade. Esc also closes panels and popovers, but not while the caret is in the Markdown source, the title, a dialog, the find bar or a field inside a panel. ⌘Z in speaker notes and detached-slide bullets is now the document's Undo. Go to Line no longer jumps to the nearest line. Whitespace-only edits now make the document unsaved and are listed in the changes panel. Ending a presentation selects the slide that was on screen, without marking the document unsaved. Also: the bottom-right panels open one at a time, a Replace All that changes nothing says "Nothing to change." and is not an Undo step, and ⌘Z in the Markdown source right after an outside change does nothing, while Edit → Undo always works.

Known issues, left. KI-49 and KI-50 are the two blank-Markdown-tab edge cases the one unsaved rule does not yet cover; nothing typed is lost. KI-44 to KI-46: the Markdown source keeps its own Undo history, separate from Edit → Undo, so keep using one of the two. KI-11: a PPTX with speaker notes may prompt for repair in PowerPoint because the notes master is not written; the problem predates this release, but live notes produce more slides with notes. KI-51: on a slide whose only visual is a diagram, the automatic layout leaves the diagram out of the PPTX, so choose an image layout; it is the one confirmed review finding that was not fixed. Earlier issues such as KI-01 (long Markdown and screen readers), KI-12 (PDFs without images) and KI-37 (image reads outside the document folder) remain. Right, planned and not yet built: FR-22 merges the two Undo histories (medium priority); FR-01 lighter rendering of long Markdown, FR-03 images and formatting in PDFs and FR-14 limiting image reads to the document folder stay high priority, alongside FR-02 printing. All automated tests pass, 1699 frontend tests in 75 files and 347 Rust tests, and the Tauri capabilities and CSP are unchanged. But the new build has not yet been checked in the running app; the manual retest of display, keyboard, Japanese IME and VoiceOver is the immediate next step.
